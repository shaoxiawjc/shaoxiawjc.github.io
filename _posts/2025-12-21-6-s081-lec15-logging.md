# Logging

# 简介

- 保证文件操作是原子性的
- 支持快速恢复

# 基本过程

基本思想：将磁盘区划分成数据区和日志区

- （log write）当更新一个文件的时候，文件系统不是直接将数据写入数据区，而是先写入日志区。比如将 45 写入 block32。会记录写入的 block num 和数据。
- （commit op）在 log 的某一个位置记录需要的操作数
- （install log）要真正执行这些操作的时候，需要将 block 从 log 分区写入对应 block。
- （clean log）一旦完成了，就清除所有的 log


考虑如下情况：
- 第一步到第二步 crash 会发生什么？没有 commit，重启的时候系统什么也不做。
- 第二步到第三步 crash 会发生什么？所有的更改都已经写入 log 了，重启之后直接 install 即可。
- 第三步到第四步 crash 会发生什么？redo log。因为我们的操作都是幂等操作（执行多次结果一样）


# xv6 中的 log

磁盘中的 log 结构，包括两部分
- head block。
	- n 代表共有多少个 block
	- 每一个 log block 实际的 block 编号（即 log 的数据最后应该放到哪个 block）
- 实际的 log block 数据块


数据会有两种状态
- in memory
- in disk

当文件系统运行的时候，内存中也会保存一份 header block 的拷贝，即 n 和 block 数组，block 数组存放的是 block 编号，并且相应的 block 也会存储在 block cache 中

xv6 中，一次文件的写事务使用 `begin_op()` 和 `end_op()`



# log_write()

文件系统调用磁盘的写入时会发生什么？


首先查看 `ialloc()` 函数，参数时 dev 代表指定设备，type 代表类型
- 先从 block cache 中读取出 block
- 查看是否是空的 inode，是的话就写入数据（文件 or 目录）

```c
// Allocate an inode on device dev.
// Mark it as allocated by  giving it type type.
// Returns an unlocked but allocated and referenced inode,
// or NULL if there is no free inode.
struct inode*
ialloc(uint dev, short type)
{
  int inum;
  struct buf *bp;
  struct dinode *dip;

  for(inum = 1; inum < sb.ninodes; inum++){
    bp = bread(dev, IBLOCK(inum, sb));
    dip = (struct dinode*)bp->data + inum%IPB;
    if(dip->type == 0){  // a free inode
      memset(dip, 0, sizeof(*dip));
      dip->type = type;
      log_write(bp);   // mark it allocated on the disk
      brelse(bp);
      return iget(dev, inum);
    }
    brelse(bp);
  }
  printf("ialloc: no inodes\n");
  return 0;
}
```


接下来进入到 `log_write()` 函数，任何一个 `begin_op()` 和`end_op()`之间的操作都会走到 `log_write()`

> 我们现在已经将要写入的 block 写入到内存中了（block cache），接下来就是应该写入到 log 中。

- 获取 log 的锁
- 查找当前的 block 编号是否已经被记录，如果已经被记录了就直接跳过


```c
// Caller has modified b->data and is done with the buffer.
// Record the block number and pin in the cache by increasing refcnt.
// commit()/write_log() will do the disk write.
//
// log_write() replaces bwrite(); a typical use is:
//   bp = bread(...)
//   modify bp->data[]
//   log_write(bp)
//   brelse(bp)
void
log_write(struct buf *b)
{
  int i;

  acquire(&log.lock);
  if (log.lh.n >= LOGSIZE || log.lh.n >= log.size - 1)
    panic("too big a transaction");
  if (log.outstanding < 1)
    panic("log_write outside of trans");

  for (i = 0; i < log.lh.n; i++) {
    if (log.lh.block[i] == b->blockno)   // log absorption
      break;
  }
  log.lh.block[i] = b->blockno;
  if (i == log.lh.n) {  // Add new block to log?
    bpin(b);
    log.lh.n++;
  }
  release(&log.lock);
}
```


# end_op()




```c

// called at the end of each FS system call.
// commits if this was the last outstanding operation.
void
end_op(void)
{
  int do_commit = 0;

  acquire(&log.lock);
  log.outstanding -= 1;
  if(log.committing)
    panic("log.committing");
  if(log.outstanding == 0){
    do_commit = 1;
    log.committing = 1;
  } else {
    // begin_op() may be waiting for log space,
    // and decrementing log.outstanding has decreased
    // the amount of reserved space.
    wakeup(&log);
  }
  release(&log.lock);

  if(do_commit){
    // call commit w/o holding locks, since not allowed
    // to sleep with locks.
    commit();
    acquire(&log.lock);
    log.committing = 0;
    wakeup(&log);
    release(&log.lock);
  }
}
```

我们首先可以先查看 `commit()` 函数的实现

```c
static void
commit()
{
  if (log.lh.n > 0) {
    write_log();     // Write modified blocks from cache to log
    write_head();    // Write header to disk -- the real commit
    install_trans(0); // Now install writes to home locations
    log.lh.n = 0;
    write_head();    // Erase the transaction from the log
  }
}
```

- 首先是 `write_log()` ，即将内存中的 block 数组里对应的 block 写入到真正的 block 里，即写数据。
- 接着是 `write_head()`，将 log header 写入到磁盘中的 log header

首先查看 `write_log()`的实现

- to 对应的内存块是最后要存放到磁盘上的 log 对应的块
- from 是内存中的 block cache 中的实际的块
即 `write_log()` 首先将数据块复制到内存中的 log 块上，然后再写入磁盘的 log 区域。
如果 crash 发生在这个时候，那么一切就好像没有发生过，因为这个时候还没有 commit，即 log header 还没被写入。

```c
// Copy modified blocks from cache to log.
static void
write_log(void)
{
  int tail;

  for (tail = 0; tail < log.lh.n; tail++) {
    struct buf *to = bread(log.dev, log.start+tail+1); // log block
    struct buf *from = bread(log.dev, log.lh.block[tail]); // cache block
    memmove(to->data, from->data, BSIZE);
    bwrite(to);  // write the log
    brelse(from);
    brelse(to);
  }
}
```

接下来是 `write_head()` ,我们称之为 commit point。
代码就是写入到磁盘中的 log header 区域。
考虑两个情况：
- crash 发生在 bwrite 之前。就好像事务没有发生一样
- crash 发生在 bwrite 之后。操作系统重启，发现 log 中还有未 install 的事务，就会开始恢复。
因此称 write_header 为 commit point。

```c
// Write in-memory log header to disk.
// This is the true point at which the
// current transaction commits.
static void
write_head(void)
{
  struct buf *buf = bread(log.dev, log.start);
  struct logheader *hb = (struct logheader *) (buf->data);
  int i;
  hb->n = log.lh.n;
  for (i = 0; i < log.lh.n; i++) {
    hb->block[i] = log.lh.block[i];
  }
  bwrite(buf);
  brelse(buf);
}
```

接下来，就是 `install_trans()` 函数了
其作用就是将 log 区域中的块实际的写入到对应的 block 中。
如果这个时候 crash 了，操作系统重启之后，还是会把所有的事务全部执行一遍，因为我们的操作是幂等操作，所以不会有问题。

```c
// Copy committed blocks from log to their home location
static void
install_trans(int recovering)
{
  int tail;

  for (tail = 0; tail < log.lh.n; tail++) {
    struct buf *lbuf = bread(log.dev, log.start+tail+1); // read log block
    struct buf *dbuf = bread(log.dev, log.lh.block[tail]); // read dst
    memmove(dbuf->data, lbuf->data, BSIZE);  // copy block to dst
    bwrite(dbuf);  // write dst to disk
    if(recovering == 0)
      bunpin(dbuf);
    brelse(lbuf);
    brelse(dbuf);
  }
}
```

在 commit 函数的末尾，会将 log 的 n 清零，也就是所谓的 `clean_log()`。
这一步如果 crash 的话，原理和 install 过程 crash 一样，也只是重新执行一遍。

> 以上的代码为 xv6 教学使用的代码，还有许多可以优化性能的地方。


# File System Recovery

操作系统重启的时候，第一件事情就是进行文件系统的恢复。

```c
void
initlog(int dev, struct superblock *sb)
{
  if (sizeof(struct logheader) >= BSIZE)
    panic("initlog: too big logheader");

  initlock(&log.lock, "log");
  log.start = sb->logstart;
  log.size = sb->nlog;
  log.dev = dev;
  recover_from_log();
}
```

其主要就是调用 `recover_from_log` 函数
```c
static void
recover_from_log(void)
{
  read_head();
  install_trans(1); // if committed, copy from log to disk
  log.lh.n = 0;
  write_head(); // clear the log
}
```


# File System Challenge

文件系统的三个挑战。

第一个部分是 cache eviction。基本原则就是，block cache 不能驱逐掉任何位于 log 中的 block cache。

在代码中，我们使用 `bpin()` 函数来增加当前 cache 的引用计数。并且在 `bget()` 中，LRU 机制不会驱逐 ref_count 为 0 的 cache。

第二个部分是 log 的区域大小。xv6 中的 log 区域是 30 个 block。一般的文件写不会超过，如果一次文件写超出了的 30 个 block，我们需要将其进行拆分。在 `filewrie()` 函数中，就有根据文件大小是否超过最大的 log blocks 而将其进行拆分的一个过程。
> `MAXOPBLOCKS` 指的是一次文件操作涉及的最大 block 数量，这里再后面的并发挑战会再提到。通过限制一次可以操作的最大 block 数量来保证并发安全。

```c

// Write to file f.
// addr is a user virtual address.
int
filewrite(struct file *f, uint64 addr, int n)
{
  int r, ret = 0;

  if(f->writable == 0)
    return -1;

  if(f->type == FD_PIPE){
    ret = pipewrite(f->pipe, addr, n);
  } else if(f->type == FD_DEVICE){
    if(f->major < 0 || f->major >= NDEV || !devsw[f->major].write)
      return -1;
    ret = devsw[f->major].write(1, addr, n);
  } else if(f->type == FD_INODE){
    // write a few blocks at a time to avoid exceeding
    // the maximum log transaction size, including
    // i-node, indirect block, allocation blocks,
    // and 2 blocks of slop for non-aligned writes.
    // this really belongs lower down, since writei()
    // might be writing a device like the console.
    int max = ((MAXOPBLOCKS-1-1-2) / 2) * BSIZE;
    int i = 0;
    while(i < n){
      int n1 = n - i;
      if(n1 > max)
        n1 = max;

      begin_op();
      ilock(f->ip);
      if ((r = writei(f->ip, 1, addr + i, f->off, n1)) > 0)
        f->off += r;
      iunlock(f->ip);
      end_op();

      if(r != n1){
        // error from writei
        break;
      }
      i += r;
    }
    ret = (i == n ? n : -1);
  } else {
    panic("filewrite");
  }

  return ret;
}
```
另一方面，block cache 的大小也应该超过 log blocks 的数量，因为在 log 写入磁盘前需要 pin 住。


第三个挑战是并发文件操作。假如有两个同时的事务，使得 log 空间中的前一半是事务1的 log，后一半是 事务2 的 log，但是两个事务都没执行完，就会卡住。因此我们需要限制并发操作文件的用户数量，并且可以使用 group commit。详细可以查看 `begin_op()` 函数
- 首先，如果当前 log 正在 commit，就 `sleep()`，因为我们不能在别的事务 install 的过程中去修改 log
- 接着，如果当前的操作是允许的最后一个并发操作，就 `sleep()` 因为有可能会超过最大的并发操作数（这里就是限制了允许的最大的用户数）

```c
// called at the start of each FS system call.
void
begin_op(void)
{
  acquire(&log.lock);
  while(1){
    if(log.committing){
      sleep(&log, &log.lock);
    } else if(log.lh.n + (log.outstanding+1)*MAXOPBLOCKS > LOGSIZE){
      // this op might exhaust log space; wait for commit.
      sleep(&log, &log.lock);
    } else {
      log.outstanding += 1;
      release(&log.lock);
      break;
    }
  }
}
```
最后再回看一下 `end_op()` 函数
- 首先是对 outstanding 减一，因为正在结束一个事务。
- 如果当前的并发操作是所有并发操作的最后一个的话，就执行 commit （即 group commit）
- 否则的话，就唤醒其他 `begin_op()` 看看它们能不能执行


```c
// called at the end of each FS system call.
// commits if this was the last outstanding operation.
void
end_op(void)
{
  int do_commit = 0;

  acquire(&log.lock);
  log.outstanding -= 1;
  if(log.committing)
    panic("log.committing");
  if(log.outstanding == 0){
    do_commit = 1;
    log.committing = 1;
  } else {
    // begin_op() may be waiting for log space,
    // and decrementing log.outstanding has decreased
    // the amount of reserved space.
    wakeup(&log);
  }
  release(&log.lock);

  if(do_commit){
    // call commit w/o holding locks, since not allowed
    // to sleep with locks.
    commit();
    acquire(&log.lock);
    log.committing = 0;
    wakeup(&log);
    release(&log.lock);
  }
}
```
