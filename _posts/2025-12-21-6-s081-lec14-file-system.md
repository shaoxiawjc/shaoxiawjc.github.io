# File System

# 文件系统简介

特点：
- 使用层级结构表示，也就是目录
- 会持久化文件

背后的一些机制：
- 抽象出对硬盘等存储介质的操作
- 计算机 Crash 的处理方式
- 磁盘上的文件系统上是如何分布的（目录，文件是以什么数据结构存储在磁盘上的）
- 文件系统如何保持高性能

一些例子：
当我们使用系统调用的时候，比如：
```c
int fd = open("x/y");

write(fd, "abc", 3);

link("x/y", "x/z");

unlink("x/y");

write(fd, "def", 3);
```

什么是文件描述符？
`write` 时没有指定 offset，offset 是存储在哪里的？
一个文件可以有多个引用
`unlink()` 之后仍然可以进行 `write()`

# 文件系统的结构层次

inode 是文件系统中对于一个文件进行表示的对象。
indoe 本身不依赖文件名进行区分，而是通过一个数字来区分。
同时，inode 必须维护一个 linked count 来表示引用这个文件的数量，只有当其为 0 的时候，文件才能被删除。
indoe 本身也维护了文件的 offset 参数。

文件系统的分层结构：

- 最底层是磁盘，实际保存数据的介质
- buffer cache 。位于内存中，防止频繁读取磁盘
- logging 层用来持久化
- inode cache 一个 inode 通常会小于一个 disk block。多个 inode 会打包在一个 disk block 中。
- inode 本身，提供 read/wrie
- 文件名，文件描述符相关操作


# 存储设备

一些存储设备类型：
- SSD
- HDD

> sector 和 blocks
> - sector 通常是磁盘上的最小读写单元，通常是 512 字节
> - blocks 代表操作系统或者文件系统视角下的数据，xv6 中是 1024 字节，对映 2 个 sector。一般一个 block 会对应 1 到 多个 sector


从文件系统的视角来看，操作磁盘实际上就是操作一个巨大的 block 数组。

xv6 中有关这个数组的布局：
- block0：xv6 不用，或者拿来作为 boot sector，来启动操作系统
- block1：一般称为 super block，用来描述文件系统，包含如磁盘上有多少个 block 构成了文件系统这样的信息。
- block2 到 block32 作为 logging 使用
- block32 到 block45 存储为 inode。一个 block 会存储多个 inode，一个 inode 是 64 字节
- 接下来是一个 bitmap block。使用位图来表示哪些 block 是空闲的
- 之后就全是数据的 block 了


# inode

一个 inode 是 64 字节，由如下部分组成：
- type 字段，表示是文件还是目录
- nlink 字段，表示又多少的文件名指向了当前的 inode
- size 字段，标识了文件数据有多少个字节
- 12 direct inode number。12 个 block 的编号，对应的 block 里就直接存放数据
- 1 indirect block number。12 个block会不够用，可以使用一个间接 block，指向的 block 里存放的还是 block 编号。

> 每一个编号是四字节，一个 block 可以存储 256 个编号

因此，一个文件是有大小上限的。

目录的表示
目录实际上就是一种特殊的 inode，即 type 为目录，然后 block 中存储的是目录的数据，也就是一条条 entries
一个 entry 的结构如下：
- 前两个字节代表目录中的文件或者 inode 编号
- 接下来的 14 个字节包含文件或者子目录的目录名
共 16 字节



创建/写文件，实际上就是对一系列的 block 的操作。
